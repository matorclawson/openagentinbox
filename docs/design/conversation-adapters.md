# Conversation adapters

Council design for the 0.12.14 base. The first change routes existing mail through an in-process adapter. The optional SQL packages are building blocks for later installations. The following worker protocol, configuration screens and social rules describe the proposed integration.

## Installation and authority

Install one independently versioned adapter executable per transport. Pair its host through a private, peer-authenticated local socket. Give each installation an opaque ID, one authorized mailbox identity, one broker grant, a capability manifest, a concurrency budget and its own health and queue counters. A supervisor may multiplex many installations. Bound connections per provider installation, never per thread. Pausing increments a persisted installation generation, stops admission and claims, and fences late callbacks. Deletion revokes the broker grant, disconnects the worker, preserves local history under retention and records the remaining uncertain operations. The core handles capabilities, including direct, group, thread, edit-own, delete-own, reaction, typing, provider-read, template and history. Missing capabilities disable their controls.

The desk should show enabled, paused, degraded, awaiting consent, gap in history, last commit, oldest queued, oldest uncertain and next retry per installation. Scope errors and alerts to that installation. Group by account and allow owners to drill down to an affected binding. Operation logs carry immutable IDs, counts and reason codes.

## Migration and transaction boundaries

1. The email extraction uses the original schemas, operation keys, address rules, MIME and LMTP/SMTP implementations. Local aliases still resolve before external policy. The original outbox and reconciliation remain authoritative for historical and pending email. No mailbox rewrite or second write per send.
2. The future adapter host installs the three optional schemas together in a migration transaction when first enabled. Add event receipts keyed by (installation, event key) with a content digest, message revision, remote object identity and source revision. Store a unique (installation, remote room, object ID, revision); multiple envelopes may describe one object. Link bodies to the existing message store. No duplicating MIME or bodies into queue rows. Keep compact tombstones beyond the supported replay/backfill horizon. Use an explicit refused-cursor response after expiry.
3. Authenticated ingress validates tenant, installation generation, event size, type, membership and current identity grant. Use opaque source identities for unmapped external data. For addressable content, insert message, binding link, durable event receipt, request if authorized and outbox obligations in one acceptance transaction. Acknowledge only after commit. On matching replay return the original receipt; conflicting payload under a key is quarantined. Never skip an access recheck when exposing a prior receipt. Track acknowledged event and message identity separately.
4. When a reply arrives first, key its conversation by the immutable remote root. Store a missing-parent reference. Fill it on arrival without changing the conversation ID. Order presentation by source timestamp and stable object identity. Apply edits by source revision; keep deletion tombstones so a late create cannot resurrect text. When two edits have no reliable order, fetch the current object or mark it unresolved. A deleted body must leave search indexes, snippets and queued notices under the retention policy.
5. A participant can have several operator-confirmed external subjects. Show the exact installation, immutable subject, target participant, privileges and affected rooms in the grant confirmation. Revoke immediately, audit separately from names and portraits, and validate the current grant inside the writer transaction. Separate membership, identity and privilege. An unmapped visitor may contribute untrusted content in an admitted conversation. Request creation, urgency, claim, resolution and delegation each require a grant. Quoted text and forwarded identity never grant authority.
6. One logical conversation may have several bindings after explicit approval. Keep a per-message audience snapshot and apply current membership on read and send. Joining two IDs alone gives no right to see or retransmit an earlier private message. Cross-channel continuity for the same approved person and agent can show both legs to those participants. Adding a third person creates a fresh audience revision and initially exposes only new authorized messages. The desk owner can read the workspace under current policy. Disclose this before mirroring private content; refuse the binding if the source policy disallows owner access. Exclude shared external-organization contexts pending a separate policy.
7. Upgrading with all adapters disabled needs no mailbox migration. Before enabling the host, take an online backup and retain the prior binary. On rollback pause workers and prevent old generations dispatching. Reopen the current compatible store with the prior binary for internal mail only, retaining pending obligations for recovery. After a public write, never overwrite the live database with a pre-upgrade snapshot. Rehearse the existing disposable upgrade/rollback script against the base installer and exact candidate; repeat with delivered and uncertain rows before claiming compatibility.

## Worker contract (proposed Go surface)

```go
type Worker interface {
    Capabilities(context.Context, Installation) (Capabilities, error)
    Receive(context.Context, Installation, func(context.Context, Event) (Receipt, error)) error
    Deliver(context.Context, Installation, Operation) (Outcome, error)
    Reconcile(context.Context, Installation, Operation) (Evidence, error)
}
```

Installation carries opaque ID, generation and broker connection reference. Event carries authenticated installation, immutable event/object/revision IDs, subject, room, thread, parent, source time, content, native mention IDs and change kind. The core resolves participants and grants. Operation includes immutable message revision, exact authorized destination, request revision, effect type and logical operation ID. Outcome distinguishes confirmed, conclusively rejected, retryable with positive nonacceptance and ambiguous. Receipt contains local ID and commit sequence. The worker process receives its installation-scoped subset over the socket; it never opens the mailbox database. Email remains embedded behind the Go acceptance and delivery hooks. New workers negotiate the protocol version on attach.

## Worker recovery and cost

An outbox row is a reference to frozen bytes or an immutable revision. Claim with one SQL update returning the attempt. A dispatcher owns an exclusive installation lease. On restart acquire that lease before marking abandoned sends uncertain. Recheck membership, request revision, consent, installation generation and send window immediately before dispatch. Serialize takeover against dispatch admission. If a post is already in flight, show takeover pending until the outcome is known; acknowledge the handoff only then. A remote acceptance cannot be recalled by a local compare-and-swap.

Reconcile by exact operation receipt or authoritative lookup. Absent that proof, hold for an operator decision against the specific attempt. Matching on text, missing a history item, or observing a timeout gives insufficient evidence for automatic retry. Keep an append-only resolution audit. Confirmed remote status can later update delivery/opened without reopening a closed request. Ignore own posts by installed identity and remote message ID, including relayed echoes with new event IDs.

One fair scheduler per host, indexed next-due seeks, bounded batches (initially 32), global outstanding cap and per-installation plus per-destination limits. Persist server-directed retry times with jitter. Claim only eligible destinations and do not allow later fragments to pass a held earlier reply. Wake after commit or when the next row becomes due. Expiry and escalation use the database clock convention, deterministic code and no model calls. Paused or disconnected transport does not pause a request deadline; put the single escalation into the outbox and notify authorized local parties. Backfill has a per-installation page and time budget plus a durable gap marker. Do not fetch years of channel history during reconnect.

## Conversation behavior

At first contact send one plain message combining the response and an accessible introduction, for example “I’m the Support AI agent operated by Example Studio. The workspace owner can read this conversation. You can ask for a person.” Bind the reservation to installation, agent, room and audience revision in the same transaction as the outbound operation. Place the same information in the profile; repeat it to a new audience. Inside template-only windows, use an approved disclosure-bearing template or wait. Answer identity questions truthfully.

Treat direct messages, explicit structured mentions and replies to the agent as addressed. Ignore other group chatter by default. A question may wait across restarts. Send one complete response, coalesce intermediate receipt changes, show optional typing only during an actual permitted response, and edit the agent's own post when supported. Keep unsupported corrections linked locally and offer one explicit follow-up. Opened means the intended reader fetched content or supplied a documented read receipt. A webhook delivery is delivery only.

Takeover requires a mapped human with claim authority. Record the change, cancel pending replies, notify the previous owner locally and suppress future automatic answers. Release or explicit handoff requires current owner and expected revision; issue the next assignee a fresh pickup deadline (normal 15 minutes, authorized urgent 2). A handoff outside the current audience requires consent or a new redacted conversation. Leave on an authorized request, disable the binding immediately and use a remote leave action only where supported. Membership loss disables future reads/sends in that scope. Retain only policy-permitted history and identity tombstones. File bodies stay outside the first connector slices; expose at most permitted metadata and never fetch arbitrary media URLs automatically.

## Threats and acceptance

Authenticate provider ingress before parsing it as an instruction. Bound decompressed bytes, nesting, attachment sizes, retries and queued bytes per destination. A public relay must verify ingress, durably stage encrypted envelopes if it takes responsibility, and carry authenticated per-installation traffic over an outbound private connection. In strict end-to-core-commit mode return success only on a signed core receipt. If the core is offline, request provider redelivery. Never acknowledge as “committed to inbox” merely because the relay received the envelope. Prohibit arbitrary callback URLs, redirects carrying credentials, cross-tenant callback routing, secret-bearing traces and raw authorization headers. Restrict certificate key retrieval to trusted origins. A compromised worker must not obtain another installation's broker grant. Retention includes source deletions, SQLite backup expiry and restoration tombstones.

For each production adapter, run the same acceptance journey with provider-shaped events and a fake remote that records actual outgoing requests:
* DM -> one request -> one disclosed reply in the same DM -> delivery/reader receipt. Duplicate event, duplicate object in another envelope, then reply-before-parent. Assert one message/request, stable chronology and no own-post echo.
* Two members share a private thread. Unmapped sender, revoked sender and a new subject using the owner's display name cannot claim. Remove the agent or participant mid-flight. Verify denial by list, detail, search, direct ID, MCP and dispatch.
* Take over, send a late reply, release, hand to a second authorized agent. Race the old deadline and worker restart. Assert the old reply is fenced, one escalation per active assignment and zero leaked content on the operator notification.
* Simulate accepted-then-timeout and kill at each transition. Reopen both stores. An unrelated destination continues, the uncertain one sends zero additional posts. A stale decision fails. A confirmed rate limit schedules a bounded retry.
* Reconnect without a public endpoint where supported; exercise a missed-event horizon and a partially completed backfill. Inject a credential canary only into the broker fixture and scan logs, response errors, database, WAL, online backup and the desk for it.
* Repeat with two installations of one type and two distinct types. Remove one. Map two external subjects to one human and approve one private conversation on both. Fetch both authorized legs; refuse copying private history into a group with another reader.

The queue, binding and request tests exercise the common primitives. Each adapter needs its own wire-level journey and broker checks before it can be enabled. Keep files, calls, productivity objects and general history mirroring outside these slices.
